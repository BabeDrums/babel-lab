# Babel Lab — Start Here

Use **Babel** as the project-facing name.

Babel Lab is the experimental sandbox/incubator for Babel ecosystem concepts. It is not a production product and it does not own cross-app truth.

## Read order

1. `BABEL_TRUTH.md`
2. Babel Truth shared authority at the pinned commit
3. this file
4. `README.md`
5. the relevant active experiment
6. relevant Lab/ecosystem items in Babel Truth Issue #1

## Core Lab rule

> **Lab is evidence, never authority.**

Lab may contain contradictory visual systems, controls, interactions, product concepts, and prototypes. Never make another product "match the Lab." There is no canonical Lab design system.

### World Lab — `world/`

### Bounded visual specimens — created only when useful

There is no active full FIRE shell replica in Lab. The former `/visual/` replica was removed from the active tree after physical review showed that reconstruction bugs, missing interactions, and visual drift obscured the real design question. Git history preserves it as rejected evidence.

Future visual/interaction specimens may be added when a question is genuinely bounded: a modal treatment, row language, selection control, motion idea, surface/material treatment, or another focused hypothesis. They do not need to live under a permanent `visual/` surface.

If an experiment requires the complete real shell, navigation, state relationships, and product interactions to judge correctly, test it in FIRE's isolated G7 successor instead.

## Product boundary

- FIRE owns FIRE product behavior, runtime, data, specs, tests, and the in-context shell.
- G7 is already isolated from V6 and is the correct place for coordinated FIRE shell iteration.
- Lab owns experiments only.
- Babel Truth owns validated shared principles/contracts after owning-product validation.

Default visual flow:

**observe in owning product → optionally run a bounded Lab experiment → try the promising decision in G7 → physical-device review → iterate in G7 → explicit shell approval/freeze → promote genuinely transferable principles to Babel Truth.**

A Lab step is optional. Do not route work through Lab merely because the question is visual.

## Process

For nontrivial Lab work use:

**Observe → Diagnose → Shape → Contract → Build → Verify → Consolidate**

For visual experiments: decide first whether the question is bounded enough for Lab. Build only enough specimen context to answer that question honestly. When full product context matters, work in the owning product preview. Promote genuinely transferable principles to Truth only after owning-product validation.
