## Shell ownership / regression rule

A solved shell role must have **one implementation owner** in Lab. Experiment CSS must not repaint it.

The shell regression gate checks real consuming pages at compact and regular widths. It is meant to catch accidental drift before a physical review, but physical-device evidence still wins when automation and reality disagree.

The exact frozen FIRE toolbar contract must be read from the **final cascade**, not one primitive file in isolation:
- `shell-primitives.css` establishes the base toolbar material
- later `frame-primitives.css` owns the final interaction-vs-material geometry
- final approved result = **44px transparent interaction host + one centered 36px visible circular material**
- the 36px circle owns the border + `#17171a` background
- symbol artwork sits above that material inside the stable 44px host

The iPhone double-ring regression happened because old Lab/WORLD CSS painted an additional full-size 44px circle underneath the canonical 36px material. The fix is **single ownership**, not removing the quieter 36px FIRE material.

A short-lived PR #23 interpretation mistakenly treated the earlier shell primitive layer as the final cascade and changed the host itself into the visible 44px circle. That interpretation was caught before physical sign-off and superseded immediately; tests now assert the real final FIRE geometry instead.

Follow-up physical iPhone review then clarified a separate universal defect: the **Info glyph itself sat too high even though the circle geometry was correct**. The cause was pseudo-generated `::before` text replacing the previously centered real button text. Lab PR #25 restored direct centered button text and added a regression for that rendering path. The remaining gate is physical recheck of the corrected `i` seating; do not reopen the circle geometry unless new device evidence shows a geometry defect.

### WORLD product job becoming testable

> **WORLD understands the real creative/project state, determines what kind of decision exists now, and helps the artist take the next meaningful step without pretending there is always one correct path.**

Phase 1 distinguishes:
1. **Required next** — a real dependency or missing relationship blocks useful progression.
2. **Suggested next** — several paths are valid, but one currently has stronger leverage from known evidence.
3. **Open choice** — no path is meaningfully superior; WORLD should say so and may offer a playful chooser rather than manufacture certainty.

Context rule:

> **Use what the work already tells us. Ask only when the answer would change the next step.**

Progress should be represented through meaningful state, dependencies, finished evidence, unresolved decisions, and direction rather than a generic percentage by default.
