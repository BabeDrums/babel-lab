# Babel Lab — Repository Instructions

Use **Babel** as the project-facing name.

## Shared authority

Read `BABEL_TRUTH.md` before substantive work, then local `START_HERE.md` and `README.md`.

## What Lab is

Babel Lab is an experimental sandbox/incubator for interaction concepts, visual systems, progression metaphors, cross-app concepts, prototype feature ideas, and future-product surfaces. Lab is not production authority.

## Truth relationship

**Lab is evidence, never authority.** Truth owns settled transferable rules; Lab may intentionally contradict Truth or other Lab experiments while testing a clearly scoped hypothesis. Do not make another product match Lab merely because an experiment exists here.

## Prototype safety

- Fake/simulated/local state is preferred unless an experiment explicitly needs otherwise.
- Never read/write FIRE production or G7 storage, schemas, or projects from Lab.
- Do not create a runtime dependency on another app.
- Do not promote prototype controls or visuals into product mechanics without review.

## FIRE Shell Lab special rule

`visual/` is currently the FIRE Shell Lab. Its starting control condition must be a **faithful observable replica of current G7 shell behavior**, not a simplified component showcase.

Before visual divergence:

- reproduce the user-facing G7 navigation/surface model needed for review
- make visible shell affordances functional, including management menus and create/edit/delete/add/custom/selection/confirmation behavior
- keep Lab-only developer navigation/explanation outside the normal FIRE canvas or behind an explicit Lab-only control
- verify parity on physical iPhone and iPad

After parity, experiments may deliberately alter visuals/interactions. Keep each divergence attributable and explicit. A winning Lab candidate is reimplemented deliberately in FIRE and validated there; Lab code is not promoted by default.

## Workflow

Use:

**Observe → Diagnose → Shape → Contract → Build → Verify → Consolidate**

For FIRE Shell Lab, Verify has two gates:

1. **control parity** with the G7 shell surfaces/behavior required for comparison
2. **candidate validation** on physical devices after deliberate divergence

For meaningful Lab changes:

**branch → experiment → verify → document learning → PR → merge**

When a result matters outside Lab, classify it:

- global transferable lesson → candidate Babel Truth change after owning-product validation
- FIRE-specific lesson → `babel-fire`
- future product-specific lesson → that product's authority once it exists
- unresolved durable conflict/question → Babel Truth Issue #1

## Continuity

Use Babel Truth Issue #1 for unresolved durable items whose loss at a chat boundary would cost real work. Do not store every brainstorm turn.

## Definition of done

A Lab pass is complete when the experiment/question is clear, production data remains isolated, intentional deviations are explicit, required interactions work for the experiment, findings are classified instead of silently promoted, obsolete replaced prototype content is cleaned up, and relevant unresolved findings are captured centrally.
